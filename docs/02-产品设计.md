# 02 · 产品设计 【提案】

## 流水线总览（产品的骨架）

```
原文导入（txt/epub/平台格式）
  → ① 术语引擎：自动抽取+维护术语表（人名/地名/功法/门派/称谓）
  → ② 状态追踪：人物状态卡（修为/关系/生死/持有物）跨章更新
  → ③ 翻译执行：术语锁定翻译 + 文风参考 + 平台风格适配
  → ④ 质量闸门：一致性自检 + 风险句标记 + 抽检采样
  → 导出（平台交付格式）+ 抽检工作台（人工终审）
```

## ① 术语引擎（差异化核心之一）

- 自动抽取：NER + 规则（中文网文的专名构造规律：X 派/X 功法/X 道人）；
- 术语表 = 词条 {原文, 译名, 首现章, 类别, 锁定状态}；
- 译名生成：首现处由 LLM 提名 2-3 个候选（附音译/意译理由），首章人工确认后**锁定**，
  后续 300 章全自动沿用——"锁定"是信任的来源；
- 漂移检测：译文里出现术语表未覆盖的新专名或同词异译，报警进待办。

## ② 人物状态追踪（差异化核心之二）

- 每个主要人物一张状态卡：修为境界、人际关系变化、生死状态、关键物品；
- 每章翻译前，把"本章出场人物的状态卡摘要"注入上下文（不是塞全本——上下文经济学）；
  防的经典事故："第 200 章死人复活""师兄变师弟"；
- 状态卡变更本身留痕，抽检工作台可审"这章为什么把 X 写成死了"。

## ③ 翻译执行

- 术语锁定翻译：术语表以硬约束注入（输出后校验术语命中率，未命中自动重译该句）；
- 文风锚：用户提供的 1-3 章理想译文作为 few-shot 风格参考；
- 平台风格适配：WebNovel/GoodNovel 各自的读者口味模板（爽点节奏、称谓习惯），
  v1 内置 2 套。

## ④ 质量闸门 + 抽检工作台（信任的另一半）

- 一致性自检：术语命中率、状态卡冲突数、文风 Embedding 漂移分（章 vs 全书均值）；
- 风险句标记：数字/时间/因果句、人物首次出场句 → 优先人工；
- 抽检采样：按风险分排序的 Top-N 章节段落推给人工，其余抽 5%——
  工作室主的账：人工从"全量校对"变"抽检 10%"；
- 工作台：双语对照、状态卡侧栏、术语表内联编辑（点错译名即刻全局生效）。

## 明确不做（M0）

- 不做发布/运营（平台投稿是平台的事）；
- 不做 Cover 生图等多模态（聚焦文本一致性）；
- 不自研模型（API 策略，评测说了算）。
