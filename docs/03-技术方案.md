# 03 · 技术方案 【提案】

## 架构

```
导入器 → 章节切分 → ┬─ 术语引擎（NER + 规则 + 锁定表）
                     ├─ 状态卡系统（抽取-更新-注入）
                     ├─ 翻译执行器（术语硬约束 + 文风 few-shot + 平台模板）
                     └─ 质量闸门（确定性检查 + Embedding 漂移）
                              ↓
                    抽检工作台（Web）+ 导出器
```

流水线本质是**有状态的批处理系统**（不是对话产品）：状态（术语表/状态卡）跨章累积，
任何一章可重译且结果确定（术语锁定保证）——可重跑性是工程基线。

## 关键实现

### 术语硬约束（不是 prompt 恳求）

1. 上下文注入术语表（当章出场子集，控 token）；
2. 输出后扫描译文：锁定术语的原文出现处，译名未按表 → 该句标记+自动重试（最多 2 次）；
3. 仍失败 → 进人工待办。命中率是 CI 指标，不是愿望。

### 状态卡系统

- 卡片 = 结构化 JSON + 变更历史（章号、变更原因引用原文句）；
- 更新器：每章译后跑一次抽取任务，diff 出变更，低置信变更挂起待人工；
- 注入器：翻译第 N 章时只注入"该章出场人物"卡片摘要——出场人物由术语引擎的
  本章命中记录决定（术语引擎与状态卡的耦合点，也是省 token 的关键设计）。

### 文风漂移量化

- 全书前 K 章译文 Embedding 均值为锚；每章漂移分 = 1 - cos(章向量, 锚)；
- 分数进质量闸门排序，>阈值章进抽检队列。漂移分与人工"文风走样"评价的相关性
  是评测指标之一（先小规模人工标注校准）。

## 评测（eval-spec）

**基准语料**：公版小说自制（版权干净）：选 3 部风格迥异公版作品（如一部武侠向、
一部世情向、一部神魔向），各人工翻译精校 10 章作为参照。指标：

| 指标 | 定义 | v0.1 门槛 |
|---|---|---|
| 术语一致率 | 锁定术语在后续章的命中率 | ≥0.98 |
| 术语召回（抽取） | 自动抽取 vs 人工标注专名 | ≥0.85 |
| 状态冲突率 | 人工审出的状态卡错误/章 | ≤0.1 |
| 文风漂移相关性 | 漂移分 vs 人工 1-5 分文风评价 | Spearman ≥0.6 |
| 抽检覆盖率 | 风险句进入抽检队列比例 | ≥0.95 |

CI 全量回归（prompt/模型变更触发），格式沿用 agentbench-local。
**基准语料+指标开源 = "中文网文翻译一致性评测基准"**，独立的社区资产。

## 技术栈

TypeScript + ESM（CLI 优先：工作室主习惯命令行/脚本交付，Web 工作台第二）；
流水线核心零重依赖；Embedding/LLM 走 OpenAI 兼容网关；
存储：SQLite（单工作室可拷走的文件即数据库——私有化友好）。

## 成本模型

百万字/月工作室：LLM 翻译+抽取+校验约 ¥800-1500（含重试），
对 ¥599 订阅是亏的——**定价修正项**：工作室档应为 ¥899 或按量封顶计费（W2 复核，
此处留待试点后用真实 token 数据重算）。
